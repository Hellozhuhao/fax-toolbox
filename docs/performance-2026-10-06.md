# Windows 工具箱性能优化

## 修改

- 会话保存：界面只复制可变列表，JSON 序列化、DPAPI 加密及原子文件替换在后台执行。250 ms 内连续请求合并，单个文件只有一个写入任务；关闭前等待保存完成。
- 会话刷新：重命名、置顶、项目变更只更新列表和标题。打开或切换会话才重建消息。相同列表数据跳过 DOM 更新，保留编辑焦点和滚动位置。
- 浏览器资源：主页、Agent 和网络管家不提前创建演示页及学习通页面。首次使用业务模块时再初始化；已有业务任务继续运行。
- 文件工具：目录枚举及搜索移出界面线程。搜索最多并行读取 4 个文件，限制 200 个文件、512 个目录和 4096 个条目，支持取消，保留受保护路径检查。
- AI 响应：网络读取及 SSE 解析不再请求返回 WPF 界面线程。
- 标签切换：删除同步 GPU 等待和切换前的重复动画帧等待；切换后的绘制等待上限 200 ms，避免隐藏或最小化页面迟迟不回调。

## 测量

环境：Windows，Intel Core Ultra 9 275HX，24 个逻辑处理器，16 GB 内存。

最终自包含 Release EXE 的隔离 `--agent-smoke` 使用 100 个会话、每个 200 条事件和 40 条历史消息，模拟 12 次连续保存。基线在后台复现旧版的序列化、加密和文件写入，避免测试本身冻结桌面；旧版实际在界面线程执行这些工作。

| 指标 | 旧实现 | 新实现 |
|---|---:|---:|
| 12 次请求的完整文件写入次数 | 12 | 1 |
| 基线完整保存累计耗时 | 1116.8 ms | — |
| 界面提交 12 次保存的累计耗时 | 旧版承担完整保存耗时 | 1.4 ms |
| 新版后台完成保存耗时 | — | 315.2 ms |
| 后台保存期间界面心跳 | — | 20 次 |
| Agent 页预先初始化的非必要浏览器控件 | 2 | 0 |

这些数字衡量本次模拟负载的保存路径，不代表全软件速度倍数、实际帧率或云端响应速度。新版后台耗时包含调度及合并等待。

## 验证

- Agent 回归：保存加密、最新快照、后续继续保存、草稿和消息节点保留、权限确认、流式输出、表格与动画、会话切换和归档。
- 搜索回归：最多 40 个结果，受保护目录过滤，取消请求生效。
- 多标签及学习通回归：`--tabs-smoke`、`--course-smoke`。
- Markdown 渲染器测试及 JavaScript 语法检查。

重新运行：构建 Windows 项目后运行 `FaxToolbox.Windows.exe --agent-smoke <结果文件>`，`<结果文件>.trace` 内的 `PERF` 行包含本机测量。
